Abstract

Video understanding benchmarks are the primary yardstick for measuring progress in video-language modeling, and a growing body of work relies on them to claim improvements. The reported benchmark scores in these works, however, are almost always produced by frameworks (e.g., lmms_eval) used as black boxes: certain evaluation choices like frame sampling, preprocessing, and input formatting are inherited from preset defaults and seldom inspected carefully. We show these unexamined choices are a major source of variance. Even for the same model checkpoint, evaluation configuration alone can shift accuracy by up to 19.5pp. Hence, it is unclear whether reported gains reflect genuine improvements in capability or differences in evaluation setup. Moreover, many benchmark samples offer little evidence of visual capability, since they can be answered without the video, and the full suites are expensive to evaluate. We address these issues in two parts. First, we curate existing suites for discriminability and efficiency, producing Meta-Video, a balanced 1,000-question benchmark over 791 videos spanning diverse tasks and durations, which largely preserves model rankings, at 5× inference speedup for a full frame-count sweep (4–128 frames). Second, we establish a standardized evaluation protocol by sweeping the configuration space to isolate choices that measurably affect results, distill them into best practices and reporting standards, and release reproducible reference scores across five models and seven benchmarks. We hope that the proposed evaluation framework and the Meta-Video benchmark will support video understanding research by providing a reproducible and efficient foundation to measure progress in a reliable way.

Evaluation Cards: Report What Produced the Score

Video models are highly sensitive to evaluation choices, yet those choices are rarely reported in full. Inspired by dataset cards, an evaluation card summarizes the complete configuration behind a table of numbers in one place. Options in bold are the ones used; a set {·} denotes a parameter sweep with one run per value. We provide a card for every table in the paper and recommend attaching one to any new video benchmark result. The card below is the one for the standardized comparison of five open models (Table 4 of the paper).

Meta-Video: An Efficient and Discriminative Benchmark

Meta-Video is a compact benchmark of 1,000 question-answer pairs over 791 videos, drawn from the evaluation sets of Video-MME, LongVideoBench, LVBench, VideoMMMU and VSI-Bench, and balanced across sources, video durations (up to one hour) and question categories. Questions that models answer correctly even when every frame is replaced by a black frame are removed, so every remaining item requires the video. The result follows the trend of the full benchmark suite while costing about 5× less to evaluate, which makes it a practical first stop for comparing new models across frame budgets.

How To Use

lmms_eval_video is a fork of lmms-eval in which every setting that changes what a video model sees lives in one YAML file: dataset, model, frames and how they are sampled, decoder, resolution, backend (HF, vLLM, or vLLM with the video fix), batch size, decoding. The runner refuses settings a model wrapper would silently ignore and writes an evaluation card next to every result. 

git clone https://github.com/soumyasj/lmms_eval_video
cd lmms_eval_video && pip install -e .

# Meta-Video, Qwen2.5-VL-7B, 32 frames, HF backend (configs/example.yaml holds every key with its default)
python eval_scripts/run_eval.py configs/example.yaml
python eval_scripts/run_eval.py configs/example.yaml --dry_run            # resolved settings + the final lmms_eval command, runs nothing
python eval_scripts/run_eval.py configs/example.yaml --set model=qwen3vl_8b --set nframes=64

# the paper's standardized comparison: five models x 4..128 frames on Meta-Video
python eval_scripts/run_eval.py configs/metav_protocol.yaml
python eval_scripts/score_metav.py --write logs/runs/metav_protocol/metav/*/*/*/*_results.json

A config toggles tasks, model, nframes, backend and vllm_fix as lists and fixes everything else; the first Meta-Video run downloads the dataset (questions and videos) from Hugging Face. The repository's DATASETS.md and MODELS.md document every video task (dataset version, split, prompt, metric) and every model family (arguments, how frames become tokens, backends).
